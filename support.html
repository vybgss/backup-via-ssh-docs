How can we help?

Set up your first backup, find answers and fix connection problems.

Get started

Your first backup takes about a minute.

  1. Add a serverClick Add Server in the sidebar or press ⌘N. Enter the host (or an alias from your ~/.ssh/config), the user and the port.
  2. Choose what to back upAdd one directory per row, or tap a suggestion such as /var/www, /etc/nginx or /etc/letsencrypt.
  3. Test the connectionClick Test Connection. If something is wrong, the app explains what and how to fix it.
  4. Back upClick Back Up Now. The first time, macOS asks you to grant access to your .ssh folder and to choose where archives are saved.

Frequently asked questions

Tap a question to see the answer.

What does the app need on my servers?

SSH access with key-based login and rsync installed — it is available on virtually every Linux and Unix server (Ubuntu, Debian, Fedora, RHEL, Alpine, FreeBSD and others). Nothing else needs to be installed on the server or on your Mac.

Which authentication methods are supported?

SSH keys only. Choose a private key in the server settings, or leave the field empty to use the keys and options from your SSH config. Password login is not supported.

My key has a passphrase. How does that work?

Turn on Key is protected by a passphrase in the server settings. When a backup starts, the app asks for the passphrase and unlocks the key in a private ssh-agent that is discarded after the run. If you mistype it, you can try again.

Tick Remember in Keychain to store the passphrase in your macOS Keychain — this is required for scheduled backups of that server. Click Forget in the server settings to remove it.

Where are my backups saved?

In the folder you choose before the first backup (~/Backup via SSH is suggested). Each backup is one ZIP file named {host}_{date-time}.zip. Change the folder in Settings → Storage & Access, or press ⇧⌘O to open it in Finder.

Every server page lists its archives: double-click one to reveal it in Finder, or right-click to move it to the Trash.

Why does the app ask for access to my .ssh folder?

The app runs in the macOS App Sandbox. Access to ~/.ssh lets ssh read your config, known_hosts and keys, exactly as it does in Terminal. You grant it once; nothing in that folder is copied or uploaded.

How do scheduled backups work?

In the server settings, set Schedule to every 6 hours, daily or weekly. Scheduled backups run while the app is open — after you close the window it keeps working from the menu bar. Bring the window back with Window → Backup via SSH (⌘1), the Dock icon or the menu bar item.

For servers with a passphrase-protected key, save the passphrase in Keychain so scheduled runs can unlock it.

Can I keep only the latest archives?

Yes. Set Keep archives in the server settings (for example, last 10). After each successful backup, older archives of that server are moved to the Trash.

Can I back up all servers at once?

Yes — click Back Up All on the Overview, in the menu bar item, or press ⇧⌘B. Servers are backed up in parallel, and you can stop any backup with Stop (⌘.).

What if a directory doesn't exist on the server?

The backup continues with the other directories. Files that vanish or can't be read during the transfer are reported in the live log but don't stop the backup.

How do I move my servers to another Mac?

Use File → Export Servers (⇧⌘E) and File → Import Servers (⇧⌘I). Exports never contain keys or passphrases — set those up on the new Mac.

Will I get notified when a backup finishes?

Yes, when the app is in the background or a scheduled backup ran. In the app you'll see a short message instead. Turn notifications off in Settings → General.

I deleted a server by mistake.

Click Undo in the message that appears right after deleting. Archives are never deleted along with a server.

What are the system requirements?

macOS 14.6 or later. The app uses the ssh, rsync and zip tools built into macOS.

Troubleshooting

When a backup fails, its page shows the error and a suggested fix. These are the most common ones.

ErrorWhat to do
Permission denied (publickey)The server rejected the key. Check the user name and that your public key is in ~/.ssh/authorized_keys on the server.
Host key verification failedThe server isn't in known_hosts yet. Choose Open SSH Session from the server's menu, accept the fingerprint once, then try again.
Remote host identification has changedThe server's host key changed. If that's expected (for example, after reinstalling), remove its old entry from ~/.ssh/known_hosts.
Could not resolve hostnameCheck the spelling of the host, or the alias in your SSH config.
Operation timed outThe server didn't answer. Check the address, the port and any firewall in between.
Connection refusedNothing is listening on that port. Check the SSH port in the server settings.
Passphrase was rejectedType it again in the unlock window. A passphrase saved in Keychain that no longer works is removed automatically.
Can't open user config file / Operation not permittedmacOS blocked access to a folder. Re-grant access in Settings → Storage & Access.

Still stuck? Click Show Log on the failed backup and include the log when you email us.
